Install Noodle with the script for the shortest path, Homebrew when you prefer
package-managed updates, or source when you need a platform without a prebuilt
binary.

## Quick install

```bash
curl -LsSf https://noodlerest.dev/install.sh | sh
```

Detects your OS and architecture, downloads the latest binary, and drops it
at `~/.local/bin/noodle`.

If `~/.local/bin` isn't on your `$PATH`, the script will let you know: just
add this to your shell config (`~/.zshrc`, `~/.bashrc`, etc.):

```bash
export PATH="$HOME/.local/bin:$PATH"
```

**Custom install location?** Set `NOODLE_INSTALL_DIR`:

```bash
curl -LsSf https://noodlerest.dev/install.sh | NOODLE_INSTALL_DIR=/usr/local/bin sh
```

**Need a specific version?** Pin it with `NOODLE_VERSION`:

```bash
curl -LsSf https://noodlerest.dev/install.sh | NOODLE_VERSION=v0.9.8 sh
```

## Windows x64 (beta)

Windows x64 binaries are included from v0.9.7. Run this in PowerShell 5.1 or later:

```powershell
irm https://noodlerest.dev/install.ps1 | iex
```

The installer downloads `noodle-windows-x86_64.exe`, verifies its SHA-256 checksum,
and installs it to `%LOCALAPPDATA%\Programs\Noodle\noodle.exe`. It adds that
directory to your user PATH. Open a new terminal after installation.

Set `$env:NOODLE_VERSION` to pin a release, `$env:NOODLE_INSTALL_DIR` to choose
another directory, or `$env:NOODLE_SKIP_PATH_UPDATE = "1"` to leave PATH alone.
For example:

```powershell
$env:NOODLE_VERSION = "v0.9.8"
irm https://noodlerest.dev/install.ps1 | iex
```

Windows ARM64 is unsupported. The executable is unsigned, so browser downloads
may trigger Windows trust prompts. Ordinary-account interactive terminal testing
remains pending. Manually dispatched CI runs provide a Windows beta ZIP with the
executable, checksums, and build information for prerelease testing.

## Homebrew

```bash
brew tap wilfredinni/noodle
brew trust wilfredinni/noodle
brew install noodle
```

Use the existing tap while the source-built Homebrew core formula awaits
acceptance. Upgrades stay under Homebrew's control.

## From source

Requires [Bun](https://bun.sh).

```bash
git clone https://github.com/wilfredinni/noodle
cd noodle
bun install
bun run build:bin
```

The binary lands at `./noodle`. On macOS, the build ad-hoc signs and verifies
it before running the compiled scripting smoke check. Move it somewhere on
your `$PATH`.

## Did it work?

```bash
noodle --help
```

You should see the CLI usage output. To launch the TUI:

```bash
noodle
```

## Supported platforms

Prebuilt binaries for these combos: others need to build from source.

| Platform | Architecture | Binary |
| -------- | ------------ | ------ |
| macOS    | arm64        | ✅     |
| macOS    | x86_64       | ✅     |
| Linux    | x86_64       | ✅     |
| Linux    | arm64        | ✅     |
| Windows  | x86_64       | Beta, unsigned `.exe` |

Both Apple Silicon and Intel Macs have prebuilt binaries. macOS release
artifacts are ad-hoc signed and verified before publication, including checks
of the downloaded artifact's checksum, signature, version, and script sandbox.

## Updating

```bash
noodle update
```

For Homebrew installations, `noodle update` prints `Run: brew upgrade noodle`
without running it, including with `--force`. Run the upgrade yourself:

```bash
brew upgrade noodle
```

Then run `noodle agent install` if you have installed the managed agent skill.
The TUI checks for available versions and shows the upgrade command in
**About and Updates**, without installing a Homebrew update.

Standalone binaries read Noodle's update manifest, download the matching
release, and verify its SHA-256 checksum before replacement. Update checks
cache release metadata for one hour; pass `--force` to bypass that cache,
or `--json` for scripted use.

For standalone installations, the TUI performs the same check when it starts
and installs an available update automatically. On Windows, the verified
update is staged until Noodle exits;
close and reopen it to apply the update. `noodle update --json` reports
`restart_required` with `log_path`. If replacement fails, inspect that log, close
all Noodle processes, and retry `noodle update` or rerun the PowerShell installer.
Progress appears in the header and beside the current version in
**About and Updates**, which is available from the command palette.

## AI Agent Skills

Install the `noodle-use` skill to teach your AI coding agent how to
create, organize, and audit noodle collections:

```bash
noodle agent install
```

Noodle stores one managed copy under `~/.agents/skills/noodle-use`, links
detected Claude, Cursor, Codex, and OpenCode installations to it, and refreshes
an existing managed installation after standalone updates. After a Homebrew
upgrade, run `noodle agent install` explicitly. For other clients, use the
skills CLI fallback:

```bash
npx skills add wilfredinni/noodle --skill noodle-use -g
```

After installing, ask your agent to scaffold a collection, audit your
requests for security issues, or convert an Insomnia export.
